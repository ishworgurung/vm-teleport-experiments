EXPERIMENT  Move a program that has an open HTTPS connection, with CRIU
QUESTION    Can CRIU keep the connection, the transaction and the login session when it moves a client to the same host or to another host?
HOW         A Python client logs in to a test server, opens a transaction on its connection and takes steps. CRIU dumps it, then restores it, under each of its TCP options. 'Same ISA' means both hosts are x86-64.

[1/6] same host, no TCP option, server on this machine
  do    start the client on h1; it logs in to the test server on this machine, opens a transaction and takes 2 steps
  prog  started (process 1391): logged in, token e7878d25, opened transaction e259 on connection 1
  prog  step 1: session counter 1, transaction step 1 (connection 1)
  prog  step 2: session counter 2, transaction step 2 (connection 1)
  do    dump the client: criu dump with no TCP option
  got   the dump failed, so CRIU left the client running. CRIU's error lines, then the client's last line:
  raw   Error (criu/sk-inet.c:191): inet: Connected TCP socket, consider using --tcp-established option.
  raw   Error (criu/cr-dump.c:1681): Dump files (pid: 1391) failed with -1
  raw   Error (criu/cr-dump.c:2111): Dumping FAILED.
  prog  step 2: session counter 2, transaction step 2 (connection 1)
  got   the test server recorded this during the case (a closing line at the end comes from this script stopping the client afterwards):
  srv   connection 1 opened, from 127.0.0.1
  srv   connection 1, /login: new session e7878d25
  srv   connection 1, /begin: transaction e259 opened
  srv   connection 1, /next: session e7878d25 counter is now 1

  srv   connection 1, /txn-step: transaction e259 is at step 2

  so    CRIU refused to dump a client with an open connection. Nothing was moved.
